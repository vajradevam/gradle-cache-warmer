# gradle-cache-warmer

Fills `~/.gradle` so projects made with `gradle init` build **offline** (exam).
Uses the machine's own `gradle` and `java` (tested: Gradle 9.0.0, OpenJDK 25.0.3).

| Path              | Purpose |
|-------------------|---------|
| `sources/warmer/` | Our sample code + JUnit 5 tests (streams, java.time, nio, Guava, records/sealed, Swing, ...). |
| `sources/tester/` | Separate student-style code, used only to verify. |
| `./warm-cache.sh` | Run once per machine **with internet**. Runs `gradle init` (application and library) in temp dirs, overlays our sources, builds with jacoco/javadoc/`./gradlew`, then rebuilds `--offline`. |
| `./test-cache.sh` | Runs a fresh `gradle init`, overlays tester sources, builds `--offline` with both `gradle` and `./gradlew`. Prints PASS/FAIL. |

Because projects are generated by `gradle init` on the machine, the cached versions
(foojay-resolver plugin, JUnit, Guava, commons-math3, launcher, wrapper distribution)
always match what students' `gradle init` produces.

Notes:
- The cache is per user: run as the account students use, or copy `~/.gradle` to every account.
- Projects that use other dependencies/plugins (checkstyle, pmd, Kotlin plugin, ...) are not cached.
- Swing tests that need a display are skipped on headless machines.
